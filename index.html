Architecture

三条启动链路

启动器会根据当前环境和检测结果决定执行链路。 正常自动模式下，上一级链路无法工作时，会进入下一条安全回退路径。

01 · PRIMARY
KRK 内核直通
优先尝试 KernelResearchKit 链路，作为默认第一启动路径。
失败 → 自动进入 DSE
KRK
02 · FALLBACK
DSE 安全回退
KRK 链路不可用时进入 DSE 路径。游戏退出后自动执行系统状态恢复。
失败 → 进入 VBS / F7
DSE
03 · LAST RESORT
VBS / F7 兜底
当前两条路径均无法执行时，进入需要重启并配合 Windows F7 启动选项的兜底流程。
F7

◫

Chrome 风格自绘标题栏

使用自定义窗口标题栏，包含自定义最小化与关闭按钮，整体界面更加统一。

游戏生命周期管理

跟踪游戏运行状态，并在游戏结束后自动执行必要的系统恢复操作。

⌁

游戏 EXE 自动发现

自动定位游戏程序并弹窗确认，也可以随时通过“重新定位游戏”手动选择。

◆

启动模式记忆

记录上一次使用的启动方式与游戏程序，减少重复选择和配置。

⌫

彻底卸载 / 一键恢复

通过六步幂等清理恢复相关服务、配置、补丁记录及缓存，不影响游戏文件。

#

RTCore64.sys 哈希比对

文件内容一致时不再重复删除和写入，降低不必要的文件变化及安全软件拦截概率。

!

RTCore64.sys 拦截检测

发现文件被安全软件隔离或阻止后，立即停止当前链路并提示恢复，不再继续盲目回退。

蓝屏历史检测

启动前扫描最近 30 天的系统蓝屏转储， 检查 SimpleSvm.sys 与 RTCore64.sys 相关历史崩溃记录。

关键崩溃代码识别

针对 0x7F、0x109、0x3B、0x50 等相关 BugCheck 进行识别。

自动切换手动模式

发现历史蓝屏记录后停止全自动链路，改为由用户手动选择本次启动方式。

失败不再自动回退

手动模式下通过左侧链路卡片选择运行方式，当前链路失败后不会自动进入下一条路径。

蓝屏信息横幅

主界面直接显示检测到的崩溃代码及转储文件，方便判断当前机器环境状态。

处置建议

检测到相关记录后弹窗说明原因，并提供升级 BIOS、退出安全软件等相关检查建议。

Getting Started

使用方法

01

放入游戏目录

将启动器 EXE 放在游戏主程序同级目录，或游戏目录的上层目录中，启动器会自动发现游戏程序。

02

运行启动器

启动后自动执行环境检测。环境符合要求后进入对应启动链路。

03

确认游戏程序

自动检测到游戏 EXE 后会弹窗确认。确认后直接运行；点击“重新选择”则进入文件选择窗口。

04

启动游戏

游戏运行期间启动器负责生命周期跟踪，并记录当前使用的运行模式。

05

退出后自动恢复

游戏关闭后自动执行对应恢复操作，尽可能将系统恢复至启动游戏之前的状态。

Notes

注意事项

系统要求

  • 仅支持 Windows 10 / Windows 11。
  • Windows 11 25H2 已实测通过。
  • 首次运行前请确认 WebView2 运行环境正常。
  • VBS / F7 链路需要重新启动 Windows，并在启动设置中选择 F7。

运行提示

  • 首次运行建议将启动器加入安全软件信任区。
  • 火绒等安全软件可能拦截新的程序哈希或驱动文件。
  • 游戏退出时请让启动器完成自动恢复流程。
  • 执行恢复 / 卸载后建议重新启动 Windows，确保系统设置完全生效。
开源许可

本项目合并了 KernelResearchKit 与 DSE-Patcher 相关源码， 并按照 GPLv3 许可进行分发。
